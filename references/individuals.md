## 1. 总述

个人（Individual）是各职能内的执行单元，由职能负责人（Lead）管理。多个个人在同一职能内并行产出独立 Artifact，由负责人合并或选择。个人属性、约束、调度机制见本文件；产出记录见 `state/individuals.json`（`references/persistence.md`）。

## 2. 个人属性定义

每个个人由以下属性定义：

| 属性 | 说明 |
| --- | --- |
| 代号 | 英文呼号，例如 alpha、beta、gamma |
| 专长 | 该个人擅长的子领域 |
| 认知风格 | 该个人处理问题的方式 |
| 偏好 | 该个人倾向的解法路径 |
| 盲区 | 该个人容易忽略的角度 |
| 使命 | 该个人在职能内承担的角色 |
| KPI | 该个人的考核项 |

## 3. 个人通用约束

| 编号 | 约束 |
| --- | --- |
| IP-1 | 不直接对用户发言 |
| IP-2 | 不审批自己的工作 |
| IP-3 | 不越界访问其他个人上下文 |
| IP-4 | 只通过 Artifact 交接 |

| IP-7 | 不因进度压力放弃寻差 |
| IP-8 | 冲突升级至职能负责人 |
| IP-9 | 负责人不可裁决时升级至 CCO |
| IP-10 | 不可裁决时升级至 H4 |

## 5. 个人调度机制

**默认调度**

| 情形 | 调度 |
| --- | --- |
| 任务简单 | 每职能调用 1 名个人 |
| 任务一般 | 每职能调用 2-3 名个人 |
| 任务复杂 | 每职能调用全部个人 |
| 高寻差需求 | 必调寻差类个人 |

**个人选择算法**

```
输入：MicroTask
1. 确定职能
2. 读取该职能个人清单
3. 按任务特征匹配专长
4. 按认知风格补齐视角
5. 按寻差需求加入寻差个人
6. 按用户画像权重调整优先级
7. 输出个人分配
```

**个人产出合并**

```
1. 各个人独立产出 Artifact
2. 负责人收集全部 Artifact
3. 负责人标注差异点
4. 负责人合并或选择
5. 差异点写入 differential_findings
6. 合并结果提交下游
```

**个人冲突处理**

```
1. 个人之间产出冲突
2. 负责人收集双方依据
3. 负责人按证据裁决
4. 无法裁决 → 升级 CCO
5. CCO 无法裁决 → 升级 H4
```

## 8. 个人相关升级与降级

| 情形 | 处理 |
| --- | --- |
| 个人连续 3 次未过门 | 记录，负责人介入 |
| 越权 | 拒绝，记录，上级介入 |
| 输出违规 | 回退，重做 |
| 个人缺失 | 负责人指定代理个人 |
| 代理行使 | 不获得否决权 |
